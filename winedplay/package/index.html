{{BRAND}} for Age of Empires II: The Conquerors

Replaces AoE2's DirectPlay with a small, modern-internet-friendly DLL shim, built on a heavily modified and customized version of Wine's DirectPlay 4 code. Players find each other through a small web-hosted PHP matchmaker (this website); once the host and the joining players have found each other, the game itself is ordinary peer-to-peer network play. No VPN, no port forwarding, no fuss.

Source code (LGPL 2.1+): okplay on GitHub · ffmpeg-7.1.tar.xz. Built on Wine and FFmpeg.

Installation

Unzip the download and copy dplayx.dll, okindeo.dll and okplay.ini into the folder that holds age2_x1.exe (original) or age2_x1.5.exe (UserPatch 1.5, strongly recommended) — usually ...\age2_x1\. Then start the game as usual, go to Multiplayer and pick {{ONLINE}} (internet) or {{LAN}} (same network).

No installer, no administrator rights, no registry changes. To remove it, delete the three files. Works on Windows 98 through Windows 11 (Windows 95 should work too).

Features

One Connection List

The Multiplayer screen lists {{ONLINE}} and {{LAN}} first, followed by Windows' classic TCP/IP and IPX connections, which still work with players who don't have this.

Windows 98 to Windows 11

The same files run on Windows 98 through Windows 11. On Windows 98 the shim talks to this site over plain HTTP and uses IPv4 only, and the intro videos use Windows' own codec.

Password Protected Games

{{BRAND}} adds a basic server password feature that was not present in the original game. Users will be prompted on lobby creation and lobby join. A blank password is an open game. The dialogue for making a password-protected game can be enabled or disabled in the INI.

Offline LAN Mode

An {{LAN}} mode is available for easy connection within a LAN without requiring an internet connection. {{LAN}} and {{ONLINE}} games can't see each other: if anyone joins over the internet, everyone picks {{ONLINE}}, including players on the same network (they still connect to each other locally).

Intro Videos Playback

The .DLL shim includes the codec to properly play the intro videos, a feature missing in Windows 10/11.

Update Notices

When a newer version is out, a box offers the download the first time you use {{ONLINE}}. It never blocks a game, and it can be turned off in the INI.

Configuration INI

Most features can be turned on or off, including disabling the shim entirely and relying on your existing Windows' DirectPlay driver for classic TCP/IP or IPX games.

The INI File

okplay.ini sits next to dplayx.dll; all settings are in its [okplay] section. The game reads it every time it starts.

mode=allWhich multiplayer the game uses. all: one list, {{ONLINE}} and {{LAN}} first, then Windows' classic connections (needs Windows' DirectPlay feature on Windows 10/11; without it only the first two are listed). oldkid: {{ONLINE}} and {{LAN}} only. windows: Windows' own DirectPlay only, as if the shim weren't there. ask: a box asks every time the game starts.

How the Networking Works

Finding Each Other

When you host on {{ONLINE}}, the shim announces the game to this website about once a second over HTTPS: its name, the player count, and the addresses it can be reached on — its local-network addresses, its IPv6 addresses, and its public IPv4 address as seen by a public STUN server. A joining player's shim reads the list, then sends the host its own addresses through the same website (a “knock”). A game disappears from the list 15 seconds after its host stops announcing it. The public list on this page never shows anyone's addresses.

Connecting Directly

Both sides then fire small UDP probes at every address the other one gave, at the same time. That opens a path through both home routers (“hole punching”), and the first path that answers is used — IPv6 directly when both sides have it. From then on the game talks straight between the PCs. It works through most home routers, phone hotspots, etc. The one case it can't handle is when both players are behind the strictest kind of router (“symmetric NAT”): there is no relay server.

Talking During the Game

Each game uses one UDP socket. DirectPlay's own control messages (joining, leaving, names, the lobby) and anything larger than about 1200 bytes travel on a reliable, in-order lane with acknowledgements, retransmission and splitting of large messages. The game's own traffic keeps the delivery guarantees the game asks DirectPlay for. Keep-alives notice a player whose game crashed within about 15 seconds; if the host leaves, another player takes over as host.

LAN Play

{{LAN}} doesn't use this website at all: the shim finds games by UDP broadcast (port 47632) on every local network the PC is on, then connects the same way.

Passwords

The password you type is never sent. Both PCs turn it into a SHA-256 hash mixed with that game's own unique ID, and DirectPlay compares the hashes. Someone watching the traffic can't read the password, and the value they see is useless for any other game.

Versions

The network protocol is versioned: games from incompatible versions don't show up for each other, so nothing half-works. Everyone in a game needs this version or a compatible one.
